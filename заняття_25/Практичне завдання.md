# Публікація сайту у Streamlit Community Cloud

## Мета

Зареєструватися у Streamlit Community Cloud, підключити свій GitHub-акаунт, розгорнути персональний Streamlit-застосунок і отримати публічне посилання на власний сайт.

У результаті ваш проєкт має відкриватися за адресою:

```text
https://назва-сайту.streamlit.app
```

---

## Що потрібно здати

Надішліть два посилання:

1. посилання на публічний GitHub-репозиторій;
2. посилання на опублікований сайт у Streamlit Community Cloud.

Приклад:

```text
GitHub: https://github.com/your-username/personal-project
Сайт: https://your-project.streamlit.app
```

Перед здачею відкрийте обидва посилання у приватному вікні браузера та переконайтеся, що вони доступні без входу у ваш акаунт.

---

## 1. Перевірте попередні умови

Перед початком переконайтеся, що:

1. у вас є акаунт GitHub;
2. персональний проєкт уже опубліковано в GitHub;
3. GitHub-репозиторій має позначку `Public`;
4. у репозиторії є головний файл `app.py`;
5. у репозиторії є файл `requirements.txt`;
6. застосунок запускається на вашому комп’ютері без помилок.

Якщо проєкт ще не опубліковано на GitHub, спочатку виконайте домашнє завдання 21.

---

## 2. Перевірте структуру репозиторію

На головній сторінці GitHub-репозиторію мають бути всі файли, необхідні для запуску сайту.

Приблизна структура:

```text
personal-project/
├── .streamlit/
│   └── config.toml
├── app.py
├── about_page.py
├── requirements.txt
├── README.md
└── .gitignore
```

Якщо ваш застосунок використовує додаткові Python-файли, зображення, JSON-файли або папки, вони також мають бути в репозиторії.

Не публікуйте:

- `.venv`;
- `venv`;
- `.idea`;
- `__pycache__`;
- `.env`;
- `.streamlit/secrets.toml`;
- паролі, токени або ключі API.

---

## 3. Перевірте `requirements.txt`

Streamlit Community Cloud створює нове середовище та встановлює бібліотеки з `requirements.txt`.

Для простого проєкту достатньо:

```text
streamlit
```

Якщо у коді є інші сторонні бібліотеки, додайте їх окремими рядками.

Наприклад:

```text
streamlit
pandas
```

Не додавайте до `requirements.txt` стандартні модулі Python, наприклад:

- `json`;
- `pathlib`;
- `os`;
- `datetime`;
- `random`.

Вони вже входять до Python.

---

## 4. Перевірте локальний запуск

1. Відкрийте папку персонального проєкту у PyCharm.
2. Відкрийте `View -> Tool Windows -> Terminal`.
3. Запустіть:

```bash
streamlit run app.py
```

4. Перевірте всі сторінки та кнопки.
5. Переконайтеся, що зображення завантажуються.
6. Переконайтеся, що в терміналі немає червоних повідомлень про помилки.
7. Зупиніть застосунок за допомогою `Ctrl + C`.

Не переходьте до публікації, якщо локально застосунок не запускається.

---

## 5. Надішліть останні зміни на GitHub

Якщо після попереднього домашнього завдання ви змінювали проєкт:

1. Відкрийте `Git -> Commit` або натисніть `Ctrl + K`.
2. Позначте потрібні файли.
3. Введіть повідомлення:

```text
Prepare app for Streamlit deployment
```

4. Натисніть `Commit`.
5. Оберіть `Git -> Push` або натисніть `Ctrl + Shift + K`.
6. Натисніть `Push`.
7. Відкрийте репозиторій у браузері та перевірте, що останні зміни з’явилися на GitHub.

Streamlit Community Cloud використовує файли саме з GitHub, а не з папки на вашому комп’ютері.

---

## 6. Відкрийте Streamlit Community Cloud

1. Відкрийте у браузері:

```text
https://share.streamlit.io
```

2. Натисніть `Sign up`, `Get started` або кнопку входу, яку бачите на сторінці.
3. Оберіть зручний спосіб реєстрації:
   - через GitHub;
   - через Google;
   - за допомогою одноразового коду на email.

Для цієї роботи найзручніше використати `Continue with GitHub`.

Навіть якщо ви увійшли через GitHub, доступ до репозиторіїв може знадобитися підключити окремо.

---

## 7. Завершіть створення акаунта

1. Якщо відкрилася сторінка GitHub, увійдіть у свій акаунт.
2. Підтвердьте вхід до Streamlit Community Cloud.
3. Заповніть коротку форму профілю, якщо вона з’явилася.
4. Натисніть `Continue`.
5. Дочекайтеся відкриття робочого простору Streamlit.

Попереджувальний значок біля `Workspaces` після першого входу є нормальним: він означає, що доступ до GitHub-репозиторіїв ще не підключено.

---

## 8. Підключіть GitHub-акаунт

1. У верхньому лівому куті відкрийте меню `Workspaces`.
2. Натисніть `Connect GitHub account`.
3. Streamlit перенаправить вас на GitHub.
4. Увійдіть у той самий GitHub-акаунт, де розміщено персональний проєкт.
5. Перегляньте запит на доступ.
6. Натисніть `Authorize streamlit`.
7. Поверніться до Streamlit Community Cloud.

Для публічного репозиторію стандартного доступу достатньо. Не надавайте доступ до приватних репозиторіїв, якщо це не потрібно для вашої роботи.

---

## 9. Створіть новий сайт

1. У робочому просторі Streamlit натисніть `Create app` у верхньому правому куті.
2. На запитання `Do you already have an app?` оберіть:

```text
Yup, I have an app
```

3. Відкриється форма публікації.

У ній потрібно вказати:

- репозиторій;
- гілку;
- шлях до головного Python-файла;
- за бажанням — коротку адресу сайту.

---

## 10. Оберіть GitHub-репозиторій

У полі `Repository` оберіть свій репозиторій.

Він може бути показаний у форматі:

```text
your-username/personal-project
```

Якщо репозиторію немає у списку:

1. перевірте, що підключено правильний GitHub-акаунт;
2. перевірте, що репозиторій публічний;
3. оновіть сторінку;
4. введіть `your-username/repository-name` вручну.

Також можна скористатися варіантом `Paste GitHub URL` і вставити посилання на файл `app.py` у GitHub.

---

## 11. Оберіть гілку

У полі `Branch` оберіть:

```text
main
```

Якщо у вашому репозиторії головна гілка називається `master`, оберіть:

```text
master
```

Назву головної гілки можна побачити на сторінці репозиторію GitHub над списком файлів.

---

## 12. Вкажіть шлях до головного файла

Якщо `app.py` лежить у корені репозиторію, у полі `Main file path` або `File path` введіть:

```text
app.py
```

Якщо головний файл лежить у папці, потрібно вказати повний шлях від кореня репозиторію:

```text
personal-project/app.py
```

Використовуйте звичайний символ `/`, а не `\`.

Не вказуйте:

- шлях до файла на своєму комп’ютері;
- `C:\Users\...`;
- адресу GitHub-сторінки замість шляху;
- назву папки, якщо `app.py` лежить у корені.

---

## 13. Оберіть адресу сайту

У полі `App URL` або `Custom subdomain` можна вказати коротку назву.

Наприклад:

```text
anna-personal-project
```

Тоді адреса матиме вигляд:

```text
https://anna-personal-project.streamlit.app
```

Вимоги до назви:

- використовуйте латинські літери;
- можна використовувати цифри та дефіси;
- не використовуйте пробіли;
- не додавайте `https://`;
- не додавайте `.streamlit.app`.

Якщо назва зайнята, змініть її, наприклад додайте своє ім’я, прізвище або кілька цифр.

Поле можна залишити порожнім — тоді Streamlit автоматично створить унікальну адресу.

---

## 14. Перевірте додаткові налаштування

Для цього проєкту `Advanced settings` зазвичай змінювати не потрібно.

У додаткових налаштуваннях можна обрати версію Python. Якщо ваш локальний проєкт працює на підтримуваній версії Python, оберіть таку саму або залиште стандартне значення.

Поле `Secrets` залиште порожнім, якщо ваш застосунок не використовує секретні ключі.

Ніколи не вставляйте секретні дані безпосередньо у `app.py` або публічний GitHub-репозиторій.

---

## 15. Запустіть публікацію

1. Ще раз перевірте:
   - правильний репозиторій;
   - правильну гілку;
   - правильний шлях до `app.py`;
   - бажану адресу сайту.
2. Натисніть `Deploy`.
3. Зачекайте кілька хвилин.

Streamlit:

1. завантажить файли з GitHub;
2. створить середовище Python;
3. встановить бібліотеки з `requirements.txt`;
4. запустить команду `streamlit run`;
5. відкриє готовий сайт.

Під час запуску праворуч можуть показуватися технічні повідомлення та журнали. Не закривайте сторінку, доки процес не завершиться.

---

## 16. Перевірте опублікований сайт

Після успішної публікації перевірте:

1. сайт відкривається без повідомлення про помилку;
2. головна сторінка завантажується;
3. навігація працює;
4. усі потрібні сторінки відкриваються;
5. зображення показуються;
6. українські символи відображаються правильно;
7. інтерактивні елементи працюють;
8. на сторінці немає приватних даних.

Якщо репозиторій публічний, опублікований застосунок також має бути публічним за замовчуванням.

---

## 17. Скопіюйте посилання на сайт

1. Відкрийте опублікований застосунок.
2. Натисніть `Share` у верхньому правому куті.
3. Натисніть `Copy link`.
4. Вставте посилання в нову вкладку браузера.
5. Відкрийте його у приватному вікні.

Посилання має закінчуватися на:

```text
.streamlit.app
```

---

## 18. Перевірте оновлення сайту

Після публікації GitHub-репозиторій стає джерелом вашого сайту.

Виконайте невелику перевірку:

1. змініть у проєкті короткий текст, наприклад опис сторінки;
2. зробіть `Commit`;
3. виконайте `Push`;
4. зачекайте трохи;
5. оновіть сторінку опублікованого сайту.

Зміна має автоматично з’явитися на сайті. Окремо повторно створювати застосунок не потрібно.

---

## 19. Додайте посилання на сайт у `README.md`

Відкрийте `README.md` і додайте:

```markdown
## Опублікований сайт

https://your-project.streamlit.app
```

Замініть приклад справжнім посиланням.

Зробіть `Commit` і `Push`, щоб посилання з’явилося на GitHub.

---

## 20. Фінальна перевірка перед здачею

Перевірте весь результат:

1. GitHub-репозиторій має статус `Public`.
2. У репозиторії є `app.py`.
3. У репозиторії є `requirements.txt`.
4. У GitHub є остання версія проєкту.
5. Сайт відкривається за адресою `.streamlit.app`.
6. На сайті немає червоного повідомлення про помилку.
7. Усі сторінки та зображення працюють.
8. Посилання на сайт додано до `README.md`.
9. Обидва посилання відкриваються у приватному вікні.

---

## Часті проблеми

### Репозиторій не з’являється у списку

1. Перевірте, що ви підключили правильний GitHub-акаунт.
2. Перевірте, що репозиторій публічний.
3. Введіть назву у форматі `username/repository-name` вручну.
4. Спробуйте вставити пряме GitHub-посилання на `app.py`.

### Streamlit не знаходить `app.py`

Перевірте поле `Main file path`.

Якщо файл у корені:

```text
app.py
```

Якщо файл у папці:

```text
folder-name/app.py
```

### Помилка `ModuleNotFoundError`

У `requirements.txt` немає потрібної сторонньої бібліотеки.

Додайте її назву, зробіть `Commit` і `Push`. Streamlit автоматично повторно встановить залежності.

### Зображення не показується

Перевірте, що:

1. файл зображення є в GitHub;
2. назва файла повністю збігається з назвою в коді;
3. великі й малі літери збігаються;
4. шлях записаний через `/`;
5. шлях указаний відносно кореня репозиторію.

На Windows `Photo.jpg` і `photo.jpg` можуть сприйматися як один файл, а на сервері Streamlit — як різні файли.

### Локально працює, а на сайті — ні

Перевірте:

- чи всі файли відправлено через `Push`;
- чи всі бібліотеки вказано в `requirements.txt`;
- чи немає абсолютних шляхів на зразок `C:\Users\...`;
- чи збігається версія Python;
- яке повідомлення показано в журналі запуску.

### Сайт не оновився після змін

1. Перевірте, що виконано не лише `Commit`, а й `Push`.
2. Перевірте останній commit на GitHub.
3. Оновіть сторінку сайту.
4. Зачекайте кілька хвилин, якщо змінювався `requirements.txt`.

### Сайт недоступний іншим людям

1. Перевірте, що репозиторій публічний.
2. Відкрийте `Share` або налаштування застосунку.
3. Перевірте, що застосунок дозволено переглядати публічно.
4. Повторно відкрийте посилання у приватному вікні.
