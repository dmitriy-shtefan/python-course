# Домашнє завдання 21. Публікація персонального проєкту на GitHub

**Дата заняття:** 20.07.2026 (понеділок)  
**Тема:** Персональний Streamlit-проєкт

## Мета

Зберегти код персонального проєкту в публічному GitHub-репозиторії та підготувати його до подальшої роботи.

## Важливо: це інструкція для PyCharm

Усі дії з Git у цій інструкції виконуються через кнопки та меню PyCharm.

Не потрібно додатково вводити `git init`, `git add`, `git commit` або `git push` у Git Bash.

---

## 1. Перевірте попередні умови

Перед початком переконайтеся, що у вас є:

1. акаунт GitHub;
2. встановлений PyCharm;
3. встановлений Git для Windows;
4. готова папка проєкту;
5. файл `app.py`, який запускається через Streamlit.

Якщо Git ще не встановлено, завантажте його з `https://git-scm.com`. Під час встановлення можна залишити стандартні налаштування.

---

## 2. Перевірте Git у PyCharm

1. Відкрийте PyCharm.
2. Відкрийте `File -> Settings -> Version Control -> Git`.
3. Знайдіть поле `Path to Git executable`.
4. Натисніть `Test`.

Якщо PyCharm показав версію Git, усе готово. Якщо Git не знайдено, встановіть Git, перезапустіть PyCharm і повторіть перевірку.

---

## 3. Увійдіть у GitHub через PyCharm

1. Відкрийте `File -> Settings -> Version Control -> GitHub`.
2. Натисніть `+` або `Add account`.
3. Оберіть вхід через GitHub.
4. Якщо відкрився браузер, увійдіть у свій GitHub-акаунт.
5. Дозвольте PyCharm доступ, якщо GitHub це запитає.
6. Поверніться в PyCharm. Ваш акаунт має з’явитися у списку.

---

## 4. Відкрийте правильну папку проєкту

1. У PyCharm оберіть `File -> Open`.
2. Оберіть саме ту папку, всередині якої знаходиться `app.py`.
3. Якщо PyCharm запитає, де відкрити проєкт, оберіть `New Window`.

На початку роботи структура проєкту має виглядати приблизно так:

```text
personal-project/
├── .streamlit/config.toml
├── app.py
├── about_page.py
└── .gitignore
```

Фото та інші файли, які використовує `app.py`, також мають бути всередині цієї папки.

---

## 5. Перевірте запуск застосунку

1. Відкрийте `View -> Tool Windows -> Terminal`.
2. Виконайте:

```bash
streamlit run app.py
```

3. Перевірте, що сторінка відкрилася без помилок.
4. Перевірте ім’я, опис, навички, інтереси, контакти та щонайменше один інтерактивний елемент.
5. Зупиніть застосунок у терміналі за допомогою `Ctrl + C`.

---

## 6. Перевірте проєкт на приватні дані

Публічний репозиторій може побачити будь-хто. Перед публікацією перевірте, що у файлах немає:

- паролів, токенів і ключів API;
- банківських даних;
- домашньої адреси або іншої інформації, яку ви не хочете публікувати.

Не додавайте до GitHub папки `.idea`, `.venv`, `venv`, `__pycache__`, файл `.env` і файл `.streamlit/secrets.toml`.

---

## 7. Створіть `.gitignore`

1. Натисніть правою кнопкою миші на папку проєкту.
2. Оберіть `New -> File`.
3. Назвіть файл `.gitignore`.
4. Додайте:

```gitignore
.idea/
.venv/
venv/
__pycache__/
*.pyc
.env
.streamlit/secrets.toml
```

5. Збережіть файл за допомогою `Ctrl + S`.

---

## 8. Створіть `requirements.txt`

1. У кореневій папці проєкту створіть `requirements.txt` з наступним текстом:

```text
streamlit
```

---

## 9. Створіть `README.md`

1. У кореневій папці створіть `README.md`.
2. Додайте назву, короткий опис та інструкцію для запуску.

Приклад:

````markdown
# Personal Project

Персональний Streamlit-застосунок з інформацією про мене, мої навички, інтереси та контакти.

## Запуск проєкту

1. Встановіть залежності:

```bash
pip install -r requirements.txt
```

2. Запустіть Streamlit:

```bash
streamlit run app.py
```
````

3. Замініть приклад опису власною інформацією про проєкт.
4. Збережіть файл.

---

## 10. Перевірте файли перед публікацією

У панелі проєкту мають бути `app.py`, `README.md`, `requirements.txt`, `.gitignore` та всі файли, які використовує застосунок.

Перевірте, що:

1. в `README.md` є назва, опис і команди запуску;
2. у `requirements.txt` є `streamlit`;
3. у `.gitignore` є `.venv/`, `.idea/`, `.env` та `.streamlit/secrets.toml`;
4. у проєкті немає приватних даних.

---

## 11. Опублікуйте проєкт на GitHub через PyCharm

Не створюйте окремо порожній репозиторій на сайті GitHub. PyCharm створить його та відправить файли.

1. Переконайтеся, що відкрито саме папку персонального проєкту.
2. Оберіть `Git -> GitHub -> Share Project on GitHub`.

У деяких версіях PyCharm цей пункт може бути у `VCS -> Share Project on GitHub`.

3. Заповніть:
   - `Repository name` — наприклад `personal-project`;
   - `Description` — наприклад `My Personal Project app built with Streamlit`;
   - `Remote` — залиште `origin`.
4. Переконайтеся, що галочка `Private` **не встановлена**. Репозиторій має бути публічним.
5. Натисніть `Share`.

PyCharm створить Git-репозиторій у папці, створить репозиторій на GitHub і підготує файли до першого commit.

---

## 12. Зробіть перший commit

Після `Share` PyCharm може відкрити вікно `Add Files For Initial Commit`.

1. Перевірте список файлів.
2. Залиште позначеними `app.py`, `README.md`, `requirements.txt`, `.gitignore`, фото та інші потрібні файли.
3. Не позначайте `.idea`, `.venv`, `venv`, `__pycache__`, `.env` або `.streamlit/secrets.toml`.
4. У `Commit Message` введіть:

```text
Initial version of Personal Project app
```

5. Якщо у вікні є кнопка `Add`, натисніть її. Це лише додасть вибрані файли під контроль Git.
6. Відкрийте `Git -> Commit` або натисніть `Ctrl + K`.
7. Позначте потрібні файли, перевірте повідомлення і натисніть `Commit`.

Якщо PyCharm одразу пропонує кнопку `Commit and Push`, вона виконає обидві дії: створить commit і відправить його на GitHub. У такому разі окремо повторювати commit не потрібно.

---

## 13. Зробіть push на GitHub

Якщо файли ще не відправлені:

1. Оберіть `Git -> Push` або натисніть `Ctrl + Shift + K`.
2. У вікні `Push Commits` перевірте, що видно `Initial version of Personal Project app`.
3. Натисніть `Push`.
4. Якщо PyCharm попросить увійти у GitHub, увійдіть у той самий акаунт.

Commit зберігає зміни на комп’ютері, а push відправляє їх на GitHub. Для завершення потрібні обидві дії.

---

## 14. Перевірте репозиторій на GitHub

1. Відкрийте GitHub у браузері.
2. У своєму профілі знайдіть новий репозиторій.
3. Перевірте, що біля назви є позначка `Public`.
4. Перевірте `app.py`, `README.md`, `requirements.txt`, `.gitignore` та всі потрібні для застосунку файли.
5. Перевірте, що `.venv`, `venv`, `.idea`, `__pycache__`, `.env` та `.streamlit/secrets.toml` немає серед опублікованих файлів.
6. Прокрутіть сторінку вниз і перевірте, що GitHub показує текст з `README.md`.

---

## 15. Скопіюйте посилання для здачі

1. На головній сторінці репозиторію скопіюйте адресу з адресного рядка браузера.
2. Посилання має виглядати приблизно так:

```text
https://github.com/your-username/personal-project
```

3. Відкрийте його у приватному вікні браузера.
4. Переконайтеся, що репозиторій відкривається без входу у ваш GitHub-акаунт.
5. Надішліть це посилання як відповідь на домашнє завдання.

## Часті проблеми

### PyCharm не бачить Git

Встановіть Git, перезапустіть PyCharm і знову натисніть `Test` у `File -> Settings -> Version Control -> Git`.

### Немає `Share Project on GitHub`

1. Перевірте вхід у GitHub через `Settings -> Version Control -> GitHub`.
2. Відкрийте `VCS -> Enable Version Control Integration`.
3. Оберіть `Git`.
4. Знову перевірте меню `Git -> GitHub` або `VCS`.

### Назва репозиторію вже зайнята

Оберіть іншу коротку назву, наприклад `personal-project-streamlit`.

### Після commit файлів немає на GitHub

Commit зберігає зміни локально. Виконайте `Git -> Push`, після чого оновіть сторінку GitHub.

### GitHub не показує `README.md`

Перевірте, що файл названо саме `README.md`, він лежить у головній папці, був позначений під час commit і відправлений через push.

- [ ] Репозиторій має тип `Public`.

- [ ] У репозиторії є `requirements.txt` і `.gitignore`.
- [ ] Усі файли, потрібні `app.py`, опубліковані.
- [ ] Немає паролів, токенів, ключів API та інших приватних даних.
- [ ] Немає `.venv`, `venv`, `.idea`, `__pycache__`, `.env` та `.streamlit/secrets.toml`.
- [ ] Посилання відкривається без входу у ваш GitHub-акаунт.
